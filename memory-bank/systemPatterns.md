# System Patterns: Hui Hui Manaʻo

## 1. Core Architecture: Monorepo with a Centralized Backend

The system is designed as a **monorepo** containing two primary packages:

1.  **`/app` (Next.js Frontend)**: A Next.js application that serves as the user-facing interface. It handles all rendering, user interaction, and API routing for data ingestion.
2.  **`/convex` (Convex Backend)**: The backend-as-a-service that manages all data, business logic, and real-time communication.

This pattern keeps frontend and backend code logically separate but co-located in the same repository, simplifying dependency management and ensuring consistency.

## 2. Data Flow Pattern: Capture -> Augment -> Organize -> Present

The application's data flow is linear and unidirectional, ensuring a predictable and scalable process for handling thoughts.

```mermaid
graph TD
    subgraph "Input"
        A[API Call / UI Input]
    end
    subgraph "Processing"
        B[Capture Service<br/>(Next.js API Route)]
        C[Store Raw Thought<br/>(Convex Mutation)]
        D[Augmentation Service<br/>(Convex Action)]
    end
    subgraph "Output"
        E[Presentation Layer<br/>(React Component with useQuery)]
    end

    A --> B
    B --> C
    C -- schedules --> D
    D -- updates data for --> E
    E -- subscribes to data from --> C
```

-   **Capture**: An API route in the Next.js app (`/app/api/injest`) acts as the universal funnel. It's a stateless endpoint responsible only for receiving data and passing it to the backend.
-   **Augment**: A Convex **action** (`convex/agent.ts`) is triggered *after* a thought is created. Using an action allows for asynchronous, long-running processes (like calling an LLM) without blocking the initial data-saving mutation.
-   **Present**: The UI is built with reactive components that subscribe directly to Convex **queries**. This means the UI will automatically update in real-time as data changes on the backend, without needing manual state management or re-fetching.

## 3. Key Technical Decisions

-   **Convex as the Single Source of Truth**: All application state resides in Convex. The Next.js frontend is intentionally kept as "thin" as possible, primarily handling rendering and user events. This centralizes logic and makes the system easier to reason about.
-   **Asynchronous Augmentation**: By decoupling the initial save (mutation) from the enrichment process (action), the system provides immediate feedback to the user that their thought has been captured. The augmentation happens in the background, and the UI updates reactively when it's complete.
-   **Two-Card Data Metaphor**: Each thought document in the database will have two key fields:
    -   `rawText`: The original, untouched input from the user.
    -   `augmentedData`: A structured object containing entities, classifications, and other metadata generated by the augmentation service.
    This preserves authenticity while providing rich, machine-readable context.
