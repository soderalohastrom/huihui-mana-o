## 3. TypeScript and Development Patterns

### Node.js Actions vs Regular Functions

**✅ Correct Pattern for AI Integration:**
```typescript
// convex/ai/augmentation.ts - Node.js action for OpenAI
"use node";
import { internalAction } from "../_generated/server";
import OpenAI from "openai";

export const augmentThoughtWithAI = internalAction({
  args: {
    content: v.string(),
    entities: v.array(v.object({...})), // Pass data as args
    recentThoughts: v.array(v.object({...})),
  },
  handler: async (ctx, args) => {
    // ✅ Initialize OpenAI inside handler
    const openai = new OpenAI({
      apiKey: process.env.OPENAI_API_KEY,
    });

    // ✅ Cannot call ctx.runQuery() - queries passed as args
    // ❌ const data = await ctx.runQuery(...) // Not allowed
    
    return await openai.chat.completions.create({...});
  },
});
```

**✅ Correct Pattern for Database Operations:**
```typescript
// convex/augmentation.ts - Regular action with database access
import { internalAction } from "./_generated/server";
import { internal } from "./_generated/api";

export const processThought = internalAction({
  args: {
    thoughtId: v.id("thoughts"),
    userId: v.string(), // ✅ Use v.string() for Clerk user IDs
  },
  handler: async (ctx, args) => {
    // ✅ Fetch data from database first
    const entities = await ctx.runQuery(internal.entities.getUserEntities, {
      userId: args.userId,
    });

    // ✅ Pass data to Node.js action
    const result = await ctx.runAction(internal.ai.augmentation.augmentThoughtWithAI, {
      content: args.content,
      entities,
      recentThoughts,
    });

    // ✅ Save results to database
    await ctx.runMutation(internal.augmentation.saveAugmentedThought, {
      ...result,
    });
  },
});
```

### User ID Handling with Clerk

**Critical Learning**: Use `v.string()` for user IDs, not `v.id("users")`.

```typescript
// ❌ Wrong: Causes ArgumentValidationError
export const createEntity = mutation({
  args: {
    userId: v.id("users"), // Expects table ID
  },
  handler: async (ctx, args) => {
    const userId = await getAuthUserId(ctx); // Returns "user_2yAe..."
    // Type mismatch error!
  },
});

// ✅ Correct: Matches Clerk's string user IDs
export const createEntity = mutation({
  args: {
    userId: v.string(), // Accepts string
  },
  handler: async (ctx, args) => {
    const userId = await getAuthUserId(ctx); // Returns "user_2yAe..."
    // Works perfectly!
  },
});
```

## 7. Troubleshooting

### Common TypeScript Errors

**"Query functions can't be defined in Node.js"**
```
Error: `getThoughtInternal` defined in Node.js is a Query function. 
Only actions can be defined in Node.js.
```
**Solution**: Move database queries out of Node.js actions, pass data as parameters.

**"Module not found" in Node.js action**
```
Error: Cannot find module 'openai'
```
**Solution**: Ensure Node.js modules are only imported in files with `"use node";` directive.

**"User ID validation error"**
```
ArgumentValidationError: Value does not match validator.
Path: .userId
Value: "user_2yAe..."
Validator: v.id("users")
```
**Solution**: Change `v.id("users")` to `v.string()` for Clerk user IDs.

### Environment Variable Issues

**"Cannot prompt for input in non-interactive terminals"**
```bash
# ✅ Use explicit configuration
npx convex dev --configure new

# ✅ Or set environment variables manually
export CONVEX_DEPLOYMENT=your-deployment
npx convex dev --once
```

**"No CONVEX_DEPLOYMENT set"**
```bash
# Check if .env.local exists and contains deployment info
cat .env.local

# If missing, reconfigure
npx convex dev --configure existing
```

### Development Server Issues

**"Functions not updating"**
- Restart `npx convex dev`
- Check file syntax with `npx convex dev --typecheck enable`
- Verify imports in `convex/_generated/api.ts`

**"Real-time updates not working"**
- Check WebSocket connection in browser dev tools
- Verify `useQuery` and `useMutation` hooks are used correctly
- Ensure Convex client is properly configured
